API ENDPOINTS
================================================================================

ENDPOINT 1: GET /api/v1/runtime/providers
  Status: HTTP 200
  Response Fields:
    • summary (system-wide statistics)
    • providers[] (per-provider health)
    • analytics[] (rolling statistics)
    • cacheStats (cache performance)
    • performanceMetrics (aggregated metrics)
    • generatedAt (timestamp)

ENDPOINT 2: GET /api/v1/runtime/events?limit=1-500
  Status: HTTP 200
  Response Fields:
    • events[] (recent provider events, newest first)
    • eventCounts (event type distribution)
    • totalEvents (count)
    • generatedAt (timestamp)

ENDPOINT 3: GET /api/v1/runtime/export
  Status: HTTP 200
  Response Fields:
    • exportedAt (timestamp)
    • summary (system statistics)
    • providerStats[] (all provider analytics)
    • recentTimeline[] (last 500 events)
    • eventCounts (aggregated)
    • performanceMetrics (system metrics)
    • cacheStats (cache performance)
  Headers:
    • Content-Disposition: attachment; filename="falcon_runtime_export.json"

DASHBOARD INTEGRATION: GET /api/v1/dashboard
  • runtimeMetrics now included in response
  • Contains: summary, currentProvider, topProviderBySuccessRate, failoversToday, cacheHitRate

MONITORING & DIAGNOSTICS CAPABILITY
================================================================================

After Phase 4.3.9, you can now answer:

Q: Why did Falcon switch from TwelveData to Yahoo Finance?
A: Check /runtime/events → ProviderFailover events show reason

Q: How many failovers happened today?
A: Check /runtime/providers → summary.totalFailovers

Q: What's the cache hit ratio?
A: Check /runtime/providers → summary.overallCacheHitRate

Q: How often does the circuit breaker open?
A: Check /runtime/providers → summary.circuitBreakerOpens

Q: Which provider is actually serving the dashboard?
A: Check /dashboard → runtimeMetrics.currentProvider

Q: Is latency increasing over time?
A: Check /runtime/providers → providers[].avgLatencyMs trends

Q: How many providers are healthy?
A: Check /runtime/providers → filter by health == "HEALTHY"

Q: What was the latest provider event?
A: Check /runtime/events (limit=1) → events[0]

PERFORMANCE METRICS
================================================================================

Memory Footprint:
  • Per-provider stats: ~1KB
  • Timeline events (500 max): ~50-100KB
  • Total overhead: <200KB for typical 3-5 provider setup

CPU Impact:
  • Event recording: O(1)
  • FIFO eviction: O(1)
  • Summary aggregation: O(providers) on request
  • P95 calculation: O(n log n) where n ≈ window size (typically 100-200)

Network:
  • /runtime/providers response: ~3-5KB
  • /runtime/events response: ~2-4KB
  • /runtime/export response: ~10-50KB depending on timeline
  • No impact on existing endpoints

Latency:
  • API response times: <100ms typical
  • Mobile UI refresh: <1s typical
  • Dashboard integration: <50ms added overhead
